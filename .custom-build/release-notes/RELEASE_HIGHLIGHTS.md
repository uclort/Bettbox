## 新增

- 内置 Tailscale 节点：内核作为独立设备加入 Tailnet，支持浏览器登录或 Auth Key 两种接入方式、设备列表与出口节点；桌面端另有「Tailscale App 共存」开关；设置入口位于「内核配置 → Tailscale」
- Tailscale 策略组：可添加多个内置节点，各自设置接入方式、出口节点和经哪个代理连接（类似 Surge 的 underlying-proxy）；设备列表里为每台设备选择经哪个组连接（组内为完整设备列表，勾选即由本组接管，默认组也可明确指定，另有自定义设备分组），也可写自定义规则，规则排在 Tailnet 兜底规则之前。配置文件里的 Tailscale 节点一并列出，可直接设为默认组或开启覆写由 GUI 接管，页面顶部预读取配置文件并提示可能的冲突
- Tailscale 策略组不再内置默认组：配置里有 Tailscale 节点就显示配置里的，没有就为空；默认组自动选配置文件里第一个节点，没有时用第一个策略组，手动指定仍然优先
- 托盘策略组菜单显示选中节点与延迟，一级菜单也补充实际节点，可选显示完整节点链路；支持 Option / Alt 显示隐藏组，Windows 增加字母快捷键
- 托盘显示策略组：在菜单栏图标旁（Windows 为悬浮提示）显示指定策略组的名称、节点、完整链路或节点延迟（如 `节点 (86ms)`），可放在网速前或后，设置页可实时预览效果；全局模式固定显示 GLOBAL、直连模式显示 DIRECT
- 托盘菜单给被固定的自动组（Fallback、URLTest 手动指定过节点）在组名前加锁标记，一眼看出当前不是按顺序选择；链路和托盘显示策略组中，被固定的组和它固定到的目标都在名称前带锁
- 托盘里可直接点选 Fallback、URLTest 的节点：点击即固定（对号变锁），再点恢复自动选择，与窗口操作一致
- 侧边栏图标、面板标题等界面自定义，隐藏策略组，Inline Provider 内容查看
- Android 应用权限页，本地网络权限运行时申请
- 应用内更新：Android 下载并安装，桌面端使用自定义更新源
- 更新设置：关于页「检查更新」旁的齿轮可开关「自动更新」（默认开），关闭后启动时不再检查更新

## 优化

- Tailscale 内置节点设置页改为状态面板：连接状态、设备名、IP、在线设备数一目了然，并可刷新
- 测速时保持托盘子菜单打开，菜单不再跳动
- macOS 网络切换、睡眠唤醒后自动恢复 TUN、DNS 与系统代理
- 内核重启与配置切换串行执行，避免启动竞态
- 内置 Tailscale 节点在更新订阅、重载配置时不再重启，Tailnet 连接不中断；配置生效后提前启动
- 同步上游 Bettbox 1.19.8 测试版：配置切换方式、智能停止、流量统计等；WebDAV 同步按配置文件保留各自的覆写脚本选择
- 开启内置 Tailscale 节点后，订阅中让 Tailnet 绕开节点的配置（TUN 排除网段、MagicDNS 服务器、hosts 等）在运行时自动忽略，不修改订阅

## 修复

- macOS 静默启动时窗口闪现
- Tailscale 共存时控制面域名返回真实 IP，Rex 等内嵌 tsnet 的应用登录不再无响应
- Tailscale 代理通道所选代理不支持 UDP 时节点启动失败（Rebind IPv4 failed），现改为经 DERP 中继连接
- Auth Key 方式的 Tailscale 节点运行中被登出后不再一直停在「需要登录」，会自动用 key 重新注册
- Tailscale 默认组掉线时 `*.ts.net` 全部解析失败：MagicDNS 改为交给所有在线的策略组解析
- Tailscale 「重新注册」改为重建节点，卡住的 Auth Key 节点可以恢复；macOS 节点连上后持续检查系统 DNS 是否仍返回「无记录」并反复清理系统缓存（覆盖约 5 分钟的否定缓存窗口），清理信号由内核进程直接发给 mDNSResponder、过程可在「日志」页查看，「刷新 DNS 缓存」也会一并清系统缓存，不再出现节点已恢复、Rex 等应用仍解析不到 Tailnet 主机而要手动 `killall -HUP mDNSResponder`
- 内置 Tailscale 节点重载配置后出现重复设备（Duplicate node key）；退出后重新登录设备名变成系统主机名
- Windows 按住 Alt 打开托盘菜单后，松开 Alt 菜单立即关闭
- 内置 Tailscale 直连节点在部分网络下无法登录、连不上（`fetch control key` 超时）：连 Tailscale 控制面、登录与 DERP 中继时不再发送会被这些网络丢弃的后量子密钥交换
- Tailscale 页面有节点连不上时，其他节点的状态和设备列表要等约 30 秒才显示
- Tailscale 设备列表里本机的 Bettbox 节点已连接却显示离线
- 配置文件里删掉 Tailscale 节点后，Tailscale 设置里仍留着它的策略组（开过覆写时无法删除）；现在打开设置时会核对全部配置文件并自动清理，节点还在其他配置文件里则保留设置
- 网络面板的日志不显示时间，现显示完整日期与时间（精确到毫秒）
- 关闭 IPv6 后 TUN 仍因检测到公网 IPv6 而接管 IPv6 流量
- macOS 在有公网 IPv6 的网络下开启 TUN 失败、无法联网（`add route: ff02:1::/32: network is unreachable`），订阅排除 `ff02::fb` 等组播地址时触发

## 移除

- 跟随上游移除独立 DNS 设置页、「网络切换时刷新 DNS」与「自动设置系统 DNS」开关（macOS 虚拟网卡的系统 DNS 托管保留）
- 移除预览版通道与「接收预览版」开关：所有版本都以正式版发布；之前开过该开关的设备照常升级到新版本

## 兼容性变更

- 与上游共用同一份配置格式，自定义项默认关闭，升级后行为保持不变
- 自定义 Snell v6 现在允许 `reuse`，obfs 与上游一致（拒绝 tls / http，允许 shadow-tls、restls、jls）

## 内核
