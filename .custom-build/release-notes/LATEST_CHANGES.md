### 2026-11-05 macOS 彻底清理 Tailscale 的 DNS 否定缓存

- 更新或重启 Bettbox 后，Rex 等应用连不上 Tailnet 主机的问题：根因是 macOS 系统 DNS 缓存。TUN 临时关闭期间系统 DNS 回落到公共 DNS，而 `ts.net` 对不存在的记录返回 NXDOMAIN（否定 TTL 300 秒），mDNSResponder 会把这个「无记录」缓存约 5 分钟。节点恢复后内核对 `*.ts.net` 已能解析（`dig` 正常），应用走系统解析仍失败（`dns-sd -G v4` 显示 `No Such Record`），面板里也看不到它们发起的连接。
- 上一版只在节点连上后固定清三次（0 / 10 / 40 秒），实测不够：缓存窗口内应用任何一次重试失败都会重新写入否定结果。现在改为持续检查：Tailscale 节点连上后先清一次，之后 10 分钟内用系统解析器查询本节点和其他设备的 MagicDNS 名，查不到就再清，恢复后停止；前 2 分钟每 10 秒检查一次，之后每 30 秒一次，连续 3 次清理无效时重启一次 mDNSResponder。
- 发清理信号改为由内核进程（root）直接发给 mDNSResponder，不再依赖子进程执行 `killall`：上一版在系统日志里看不到 `SIGHUP: Purge cache`，说明子进程没把信号送到。「日志」页现在会记录开始检查的域名数量、清理是否成功、`系统 DNS 正常` 或 `系统 DNS 已恢复正常（共清理 N 次）`。
- 「网络监控 → 刷新 DNS 缓存」仍然同时清内核缓存和 macOS 系统缓存，不用再手动执行 `sudo killall -HUP mDNSResponder`。
- 其他平台行为不变（系统缓存清理只在 macOS 生效）。

### 2026-11-05 Tailscale 不再内置默认策略组

- 全新安装开启内置节点后，策略组列表是空的：配置里有 `type: tailscale` 节点就显示配置里的，没有就等你自己添加。之前会凭空出现一个 `Bettbox-Tailscale`，想用别的名字还得先改名。升级前已经开启的用户，原来的节点仍会自动迁移为策略组，身份和设备名不变，不用重新登录。
- 默认组改为自动选择：优先配置文件里第一个 Tailscale 节点，没有时用第一个自己添加的策略组；一个节点都没有时不生成 Tailnet 兜底规则。手动点「设为默认组」仍然优先。
- 配置文件里的节点可以直接设为默认组，不需要先开覆写。
- 默认组也可以删除，删除后自动回退到上述规则选出的组。
- 各组的设备与自定义规则仍排在兜底规则之前；兜底规则的目标由界面先下发占位名，内核按实际配置替换，避免指向不存在的出站。

### 2026-11-05 Tailscale 策略组设备列表改为勾选

- 列表里看不到的设备放在底部「自定义设备」分组，可手动添加，取消勾选即删除。
- 内置节点主页去掉顶部的状态面板和「重新注册」，状态、登录、重新注册都在具体策略组里；主页每个策略组前有状态圆点。

### 2026-11-05 Tailscale 策略组：点选设备、默认组也可指定设备

- 策略组详情页列出 Tailnet 里的设备，点一下就加入本组，不用再手动输入；每台设备后面显示它当前在哪个组。手动添加仍保留。
- 默认组也可以明确指定设备，规则同样排在兜底规则之前。没有指定给任何组的设备显示「未指定」，由默认组兜底。设备列表里的「连接方式」可以选任一组，也可以选「未指定（默认组兜底）」；在组里删除设备也是改回未指定。
- 设为默认组时不再清空它已指定的设备。
- 默认组没连上时，设备列表改用其他已连接组看到的设备，不会因为默认组离线就只剩手动输入。
- 修复默认组掉线时所有 `*.ts.net` 都解析不出来：MagicDNS 原来只交给默认组，默认组没登录就返回 SERVFAIL，即使经其他组的 Rex 设备已经连通，Rex App 也因为拿不到 IP 而连不上。现在 MagicDNS 交给所有生效的组并行解析，任何一个组在线就能解析。
- 「重新注册」改为重建节点：原来是在卡住的节点里再登录一次，实测无效；现在会新建节点并用 key 注册，效果与改设备名再改回来相同。
- macOS：Tailscale 节点每次连上后自动清一次系统 DNS 缓存。节点掉线期间 macOS 会把 `*.ts.net` 的「解析不到」缓存约 20 分钟，节点恢复后 Rex 等应用仍连不上，以前要手动执行 `sudo killall -HUP mDNSResponder`。
- Auth Key 节点没注册上时不再一律提示「key 无效、已用过或已过期」：只有控制面明确拒绝 key 时才提示换 key，连不上控制面等网络原因显示「注册未完成，会自动重试」并附真实错误。
- 修复 Auth Key 方式的节点运行中被登出（例如在 Tailscale 后台删除了设备）后一直停在「需要登录」、只能重启 Bettbox 才恢复：现在会自动用 key 重新注册（约 20 秒内），状态面板显示控制面返回的真实错误，而不是「连不上 Tokyo 中继」这类未登录时的连带提示。

### 2026-11-05 Tailscale 策略组

- 内置节点设置页改为「Tailscale 策略组」列表：每个组是 Tailnet 中的一台独立设备，可以添加多个。每个组可单独设置接入方式（浏览器登录或 Auth Key）、设备名、出口节点、子网路由，以及「通过」某个代理连接（控制面、DERP、UDP 都经该代理，效果同 Surge 的 `underlying-proxy`）。
- 其中一个是默认组，承接 `*.ts.net`、`100.64.0.0/10` 兜底规则和 MagicDNS；其他组只接管指定给它的设备和自定义规则（如 `DOMAIN-SUFFIX,example.ts.net`，目标自动设为这个组），这些规则排在兜底规则之前，不会被直连的默认组盖掉。设备列表里每台设备右侧可选择经哪个组连接，同一台设备只会在一个组里。
- 非默认组 Auth Key 留空时使用默认组的 key。注意同一个 key 在 Tailnet 中仍是两台设备（key 需勾选 Reusable）；两个组不会共用一个身份，那样两个会话会互相顶替。
- 配置文件里自己写的 `type: tailscale` 节点也列在策略组里，标注「配置文件」，右侧有「覆写」开关：开启后运行时用 GUI 的设置替换配置文件中的同名节点，不改配置文件，第一次需要登录一次；当前配置文件里没有这个节点时覆写不生效，相关规则也不会下发。没开覆写时只读显示参数，也可以直接登录 / 退出。
- 页面顶部会预读取全部配置文件，列出定义了 Tailscale 节点的配置文件，并提示可能的影响：身份目录与 Bettbox 相同（两个节点互相顶替）、与策略组同名、设备名重复、配置文件里指向它的规则排在 Bettbox 的 Tailnet 规则之后。
- 升级后原来的主节点自动成为默认组，原来的「代理通道」自动成为一个策略组（`Bettbox-Tailscale-Proxy`），身份目录和设备名都不变，不需要重新登录。
- Tailscale App 共存不受影响，行为不变。

### 2026-11-05 修复代理通道节点启动失败

- 「代理通道 → 通过」选的代理不支持 UDP（或 UDP 建立失败）时，代理通道节点启动报 `Rebind IPv4 failed: failed to bind any ports`，一直连不上。现在会自动改为只经 DERP 中继（走代理的 TCP）连接，节点正常启动；日志里会有一条「无法建立 UDP，改为仅经 DERP 中继」的提示。所选代理支持 UDP 时行为不变。

### 2026-11-05 内置 Tailscale 节点：指定设备经代理连接

- 设置 → 内核配置 → Tailscale → 内置节点的设备列表里，每台设备右侧新增「经代理连接」开关；不在列表里的设备可在「代理通道 → 手动添加设备」填 MagicDNS 名或 Tailscale IP。
- 在「代理通道 → 通过」选择一个策略组（如 Global）后，这些设备经另一个内置节点 `Bettbox-Tailscale-Proxy` 访问，它的控制面、DERP 与 UDP 都经所选代理发出；其余设备仍走原来的直连节点。效果与 Surge 中 `underlying-proxy` 的 Tailscale 段 + 按设备规则相同。
- 代理通道节点在 Tailnet 中是另一台设备（设备名为主设备名加 `-proxy`），需要单独登录一次，登录、退出、重新注册按钮在代理通道里；接入方式与 Auth Key 跟主节点一致。没选代理时不生效，并提示「请先选择代理」。

### 2026-11-03 内置 Tailscale 节点

- 网络设置新增「Tailscale」分组。新开关「内置 Tailscale 节点」（默认关闭）：Bettbox 内核作为一台独立设备加入 Tailnet，`*.ts.net` 与 `100.64.0.0/10` 自动转给它，不需要安装或运行 Tailscale App。需要开启虚拟网卡或系统代理；只负责本机访问 Tailnet，不能让其他设备访问本机。
- 齿轮内可查看节点状态（设备名、Tailnet IP、账号），点「登录 Tailscale」在浏览器授权，登录状态保存在本机，重载配置无需重新登录；也可填 Auth Key、设备名、出口节点，或关闭子网路由。
- 原「Tailscale 共存」改名「Tailscale App 共存」，仍需 App 保持运行。两个都开时以内置节点为准。新增「Tailscale 接入说明」，介绍两种方式的区别、同时开启的效果，以及什么时候需要 Tailscale App。Android 只显示内置节点，接入说明也换成 Android 版本：系统同一时间只允许一个 VPN，所以没有 App 共存。
- 更新订阅、同步规则或修改与节点无关的设置时，内置节点不再重启，Tailnet 连接（例如 Rex 访问 VPS）不会中断；只有改设备名、接入方式、Auth Key、出口节点或子网路由时才重新连接。配置生效后节点立即在后台启动，第一次访问 Tailnet 不用等。
- 内置节点设置页新增「设备」列表：显示 Tailnet 中所有设备的在线状态、IP、系统，以及当前是直连还是经 DERP 中继，点按复制 IP，页面打开时自动刷新。
- 修复切换开关或重载配置后，内置节点在 Tailscale 后台显示「Duplicate node key」、状态一直停在「正在连接」：新节点启动前会先关掉旧节点。
- 内置节点不会出现在 include-all 策略组里，不参与测速和自动选择。

### 2026-11-02 托盘显示策略组选中目标、Android 应用权限页

- Fallback、URLTest 等自动选择的策略组，托盘子菜单中的节点改为灰色（与右侧延迟同色），点击无反应且不会关闭菜单；只有手动选择（Selector）组的节点可点选。
- 修复 macOS 按住 Option 打开托盘（显示隐藏策略组）时，点击延迟测试没有加载动画、延迟不刷新的问题。
- Windows 支持按住 Alt 点击托盘图标临时显示隐藏策略组（对应 macOS 的 Option）。
- 修复 Windows 按住 Alt（Parallels 里的 Option）打开托盘菜单后，松开 Alt 菜单立即自动关闭：菜单跟踪期间吞掉 Alt 按键消息，与 macOS 松开 Option 菜单仍保持打开一致。

- Tailscale 共存开启后，`tailscale.com` / `tailscale.io`（控制面、登录、DERP）固定返回真实 IP，DNS 服务器与分流规则不变；修复开启虚拟网卡时 Rex 等内嵌 Tailscale（tsnet）的应用点「Sign in」一直无反应。请勿把 `tailscale.com` 填进 MagicDNS 域名，MagicDNS 无法解析它，浏览器会报 NXDOMAIN。

### 2026-10-31 Tailscale 共存

- 网络设置新增「Tailscale 共存」（桌面端，默认关闭）：Tailnet 网段不进虚拟网卡，`*.ts.net` 返回真实 IP 并交给 `100.100.100.100` 解析，系统代理自动绕过 Tailnet；各项可自定义，支持一键恢复默认。
- 订阅里写的 `tun.route-exclude-address` 不再被客户端设置覆盖，改为合并生效（包括热更新）。
- 内核访问被排除的网段时不再强制绑定 en0，按系统路由走 Tailscale。
