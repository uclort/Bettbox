### 独立网络面板

- 桌面导航以一个“网络面板”替换原“请求 / 连接 / 日志”三个页签，托盘菜单在“虚拟网卡”上方增加同一入口并以上下分割线隔开；Android 在“更多”中增加内嵌入口。
- 桌面入口改为启动独立网络面板进程，在 Dock/任务栏中使用逐像素保留 Bettbox 原图标、仅于右下角叠加蓝色网络波形徽标的专属图标；关闭面板不影响 Bettbox，Bettbox 退出或崩溃时会连带关闭面板。
- 移除 `desktop_multi_window` 及子引擎全插件重复注册，修复打开网络面板后 `tray_manager` 事件通道被覆盖、托盘左右键无法弹出菜单或主窗口的问题。
- 面板通过现有本地 UDS/TCP 控制通道复用主进程数据和操作，统一展示最近请求、活动连接、DNS、设备、流量统计和日志，不创建第二个 Mihomo 实例。
- 最近请求与活动连接按 Mihomo `TrackerInfo` 的进程、来源地址、目标地址、网络协议、规则类型和出站链动态分类；支持搜索、全部表头升降序切换、拖拽调整列宽，以及选中后展开底部详情。macOS 进程分类、连接表和详情读取所属 App 的原生图标。
- 修复惰性列表复用可见行时短暂沿用上一进程图标、无图标行不恢复默认状态的问题；进程侧栏优先使用 Mihomo 提供的有效 App 路径，macOS 继续直接通过 `NSWorkspace` 读取对应应用图标。
- 手动拖拽的请求/连接表列宽写入本机偏好设置，重新打开网络面板后自动恢复；规则类型改为独立灰色标签并与规则参数区分，策略列只显示最终策略，完整策略链仅在详情中展示。
- 请求详情面板增加纵向拖拽手柄，可上下调整高度；IP 信息区分客户端地址、目标地址、内核 Fake-IP、实际出站地址和直连目标/代理节点远端地址，GeoIP/ASN 仅在内核或现有 GeoIP 查询能够返回时显示。
- 详情页移除 Mihomo 不支持的 HTTP 请求/响应报头与正文页签；“计时 & 日志”改为“Mihomo 链路”，优先展示 custom-mihomo 随当前连接返回的 DNS 尝试、规则匹配、策略链和真实 socket 建立事件，不再混入同进程的其他请求日志。
- 修复面板打开时同一进程图标被大量并发读取、macOS 主线程反复编码全尺寸 PNG，导致面板 CPU、内存暴涨并卡死的问题；图标请求按进程合并，原生端固定输出 64×64 PNG。
- 修正顶栏搜索框对齐；设备页仅按内核可确认的本机进程、网络来源及活动/历史状态分类，不再伪造静态 IP、网关或接管模式；日志只按实际事件的 `error / warning / info / debug` 级别筛选。
- 请求与连接列表移除无意义的 ID 展示，首列仅保留红色错误、黄色活动、绿色结束、灰色其他状态点；“日期”列改为“时间”并按本机时区显示，策略名称中的连续空白统一压缩，并使用固定像素间隔规避旗帜 Emoji 字体回退造成的异常大空格。
- 请求、连接、DNS 和设备表改为固定行高的惰性列表，只创建可见行并复用滚出视口的元素；实时事件最多每 250 ms 刷新一次，避免记录增长后整表重建造成持续卡顿。水平、垂直滚动保持独立并裁剪到列表区域。
- DNS 按 Mihomo 配置键 `default-nameserver / nameserver / fallback / proxy-server-nameserver / direct-nameserver / nameserver-policy / hosts`、系统 `/etc/hosts` 和运行时 `dnsMode` 分类；运行时记录仅保留带有效目标 IP 的域名。
- 流量页直接显示 Mihomo 的实时与累计上传/下载，连接记录只用于按出站链、规则类型、进程、来源地址、网络协议和目标主机聚合明细，不再把有限历史记录求和冒充内核总流量。
- 无进程、无来源地址的 Mihomo 内部连接不再污染请求与连接列表；具有真实客户端的 `REJECT` 规则命中继续保留并显示红色状态点。
- 请求和日志到达后实时推送；活动连接在连接页以 250 ms 快照增量更新，并复用主进程核心，不创建第二个 Mihomo 实例。
- Mihomo 在连接加入和离开时均回传同一连接 ID，请求记录按 ID 更新，最近请求页由事件立即刷新活动/完成状态，不再进行 250 ms 主动快照；订阅推送显式刷新 socket，避免退化为 5 秒兜底刷新。浏览器复用同一 HTTP/2 或 QUIC 连接时不会伪造新的 HTTPS 请求记录。
- 修复 macOS 首屏部分进程图标保持占位、滚出再滚回才显示的问题：缺少进程路径时由 `NSWorkspace` 按运行中 App 名称读取，同进程记录复用快照中的有效 `.app` 路径。详情 IP 卡允许换行并完整显示长地址。
- 独立面板不记录、不恢复也不主动激活 Bettbox 或其他应用；除主进程负责其生命周期外，Dock、Cmd+Tab 和关闭窗口后的前台选择完全交给 macOS，表现为两个互不关联的普通 App。
- 主进程处理完网络面板的一次性 UDS/TCP 请求后立即刷新响应并关闭服务端 socket，订阅连接仍保持长连，避免反复刷新面板持续泄漏文件描述符。
- HTTP 报头、正文、流量捕获和 MitM 不伪造，网络面板不展示 Mihomo 没有提供的数据入口。

### 托盘与代理开关

- 托盘菜单将系统代理置于虚拟网卡上方；“显示窗口 / 网络面板 / 系统代理 / 虚拟网卡 / 重启内核 / 退出”分别显示 `⌘M / ⌘D / ⌘S / ⌘E / ⌘R / ⌘Q`，重启内核移到一级菜单，重启软件移入工具子菜单。
- 系统代理与虚拟网卡均关闭时，托盘上传、下载立即归零并保持灰色；托盘改为监听内核实际 TUN 状态，重新开启系统代理或虚拟网卡完成后强制同步最终状态，图标与网速恢复系统高亮色，不再停留在启动过程中的灰色快照。
- Bettbox 仅关闭系统代理开关时不再主动关闭 macOS、Linux 或 Windows 当前系统代理；只有本进程成功启用过系统代理后才负责关闭，确保系统代理与虚拟网卡均关闭时 Bettbox 不参与系统网络设置。
- 自定义构建 Action 新增仅构建并发布 macOS Apple Silicon 的手动选项；启用时 Release 和 Sparkle 更新源只处理 arm64 DMG，不启动 Android、Windows 或 macOS Intel 任务。

### 内网接口 DNS

- Mihomo direct proxy 新增 `dns-follow-interface`，绑定 en5 的内网直连代理会自动使用 en5 当前 DNS 解析目标域名。
- 新增默认开启的 `allow-other-interface`；en5 不存在、未运行或没有可用地址时，连接和 DNS 自动切到当前默认接口，插入内网 Wi-Fi 后无需手动改为普通 DIRECT。
- macOS 优先读取系统已有的 en5 作用域 DNS；正常状态不轮询，解析失败或网络重置时才刷新并重试。
- 覆写脚本不再为内网域名重复维护 `nameserver-policy`，固定 hosts 仍保留为注释回退。

- “增强工具”中的“托盘点击行为”和“显示托盘网速”恢复为两条独立设置，不再合并在同一卡片中。
- Android 首页总开关避让悬浮底部导航，页面底部同时增加完整的按钮滚动留白，避免按钮被遮挡或覆盖仪表盘内容。

### TUN 与系统 DNS

- macOS 将会导致微信聊天图片/表情一直 Loading 的 Mihomo `system` TUN 栈统一映射为 `mixed`；用户显式选择 `mixed` 或 `gvisor` 时保持原值。
- 桌面端切换 TUN 栈时完整重启内核，不再热重建运行中的 TUN；失效的核心 IPC socket 会立即清除，内核异常退出时记录真实退出码和 stderr，避免弹出次生 `Broken pipe`。
- 移除“自动设置系统 DNS”开关；macOS 开启 TUN 时自动托管系统 DNS，关闭 TUN 或停止应用时自动恢复。
- 旧配置中的开关字段不再生效，避免关闭 DNS 托管后出现 TUN 流量异常。
- macOS 启动 TUN 前检测其他 VPN 遗留的 `1.0.0.0/8` 路由；发现冲突时保持 TUN 关闭并提示对应接口，避免直接启动失败。
- 修复 macOS 关闭旧 TUN 时 `ENOTSOCK` 未被识别为关闭，导致 `batch read packet` 无限刷屏、核心与界面 CPU 满载的问题；关闭感知包装器保留 Mixed/GVisor 方法集，修复选择 `mixed` 后核心崩溃、界面继而报 `Broken pipe` 且无法联网的问题。

### 节点测速

- Provider、Fallback、策略组和手动测速在 Mihomo 内共用全局测速管理器，实际网络请求总数最多 16；手动与后台采用公平双队列，后台会优先获得下一个空闲槽并与手动任务轮转，不会等待整批手动测速结束。
- 删除 Dart 与桥接层的前置排队、防抖和结果缓存，手动请求立即进入核心登记；不同策略组可同时提交，同一节点命中在途任务时只增加等待者。桥接旧 `mBatch` 的结果泄漏同时移除。
- 核心测速超时调整为 10 秒，桥接等待为 12 秒；解析失败、节点不存在或其他异常都会结束加载并显示检测失败，避免秒出超时、永久转圈和结果跳变。
- Provider 后台健康检查失败不再覆盖页面已有测速结果；只有用户主动测速才写入失败终态。
- 覆写脚本使用全局 `latencyTestUrl` 统一 OwO、源 Provider、Inline Provider 和策略组测速地址，默认值改为 `http://www.gstatic.com/generate_204`；核心对 HTTP 测速只发送一次标准 GET。
- Bettbox 开启“覆写测速链接”时，同时覆盖策略组和 Provider 健康检查地址。
- 增加节点测速全链路诊断日志，以 request ID 串联 Dart、桥接和 Mihomo 网络阶段，并记录 Provider batch ID、失败阶段、context、错误类型及各段耗时；不改变测速、并发、超时或重试行为。
- 应用内日志与请求记录容量从 256 提高到 1024 条，完整保留一轮约 90 节点的详细测速记录。
- 配置重载时立即关闭旧 Proxy Provider，取消上一代健康检查，修复首次启动或覆盖安装后同一 Provider 出现两批测速的问题。
- Provider 健康检查与 Bettbox 主动测速按实际节点实例、地址和期望状态复用同一个在途请求；每个调用者保留自己的超时，Provider 超时不会提前终止仍在等待的前台测速。
- 节点网络超时从真正获得执行槽后开始，排队不再导致“尚未测速即超时”；删除成功结果 1 秒保留，测速结束后立即移除状态，之后的手动测速一定真实发起网络请求。成功、失败均不缓存，也不增加重试。
- Provider 整批健康检查只合并在途触发，不缓存完成结果；配置重载或 Provider 更新替换节点实例时取消旧任务，防止旧结果回写或新节点错过首轮检查。
- 用户显式使用 HTTP 测速时只发送一次标准 GET，避免部分线路随机断开 HEAD；不增加失败重试。
